ШІ на занятках па праграмаванні: як захаваць самастойнае рашэнне

Сцэнарый занятку з абмежаванымі AI-падказкамі: контрпрыклад, тлумачэнне стану алгарытму і праверка самастойнага рашэння

Калі вучань здаў працуючую праграму, выкладчык яшчэ не ведае, чаму ён навучыўся. Праграма магла быць напісаная самастойна, сабраная з падказак або цалкам атрыманая ад мадэлі. Для навучання трэба адрозніваць якасць гатовага артэфакта і здольнасць рашыць наступную задачу.

AI-памочніка карысна ўключаць у занятак з загадзя зададзенай роляй: удакладніць умову, даць абмежаваную падказку, прапанаваць праверку або разабраць памылку. Кантроль самастойнага навыку павінен заставацца асобным этапам.

Пытанне ўплыву GPT на праграмаванне і навучанне разглядалася ў працы 2023 года пра ўплыў GPT. Ацэнкі канкрэтных мадэляў таго перыяду не апісваюць аўтаматычна сучасныя інструменты. Ніжэй — навучальны сцэнарый, які не залежыць ад рэйтынгу мадэлі.

Пачаць з дамоўленасці пра выкарыстанне памочніка

Растлумачце, на якім этапе дапушчальныя падказкі і што вучань павінен прадставіць разам з кодам. Для трэніровачнага задання гэта могуць быць уласная ідэя, знойдзены контрпрыклад і тлумачэнне выпраўлення. Для кантрольнай работы ўмовы задаюцца асобна.

Выкладчыку варта загадзя падрыхтаваць рашэнні, памежныя выпадкі і крытэрыі праверкі. Мадэль можна выкарыстоўваць як дадатковую крыніцу варыянтаў, але створаны ёю адказ не становіцца эталонам без праверкі.

Не загружайце ў знешні сэрвіс персанальныя звесткі навучэнцаў і закрытыя матэрыялы курса па-за ўзгодненым парадкам. Кіраўніцтва UNESCO па генератыўным AI ў адукацыі разглядае педагагічную дарэчнасць і абарону даных як самастойныя пытанні ўкаранення.

Разабраць памылку, якую лёгка прапусціць

Вучэбная задача: знайсці максімальную суму непустога непарыўнага фрагмента паслядоўнасці цэлых лікаў.

Ва ўмове важныя словы «непустога» і «непарыўнага». Для [-5, -2, -7] правільны адказ роўны -2. Значэнне 0 азначала б, што рашэнне дазволіла пусты фрагмент, хоць умова гэта забараняе.

Да атрымання гатовага кода папрасіце вучня сфармуляваць, што захоўваецца пасля апрацоўкі чарговага ліку. Падказка памочніку можа выглядаць так:

Не пішы рашэнне цалкам. Задай адно пытанне, якое дапаможа праверыць, ці дапускае мой алгарытм пусты фрагмент. Пасля майго адказу прапануй адзін кароткі контрпрыклад.

Такі фармат абмяжоўвае аб'ём дапамогі, але сам па сабе не гарантуе захавання межаў мадэллю. Выкладчык павінен бачыць, якая падказка была выдадзеная і што вучань зрабіў пасля яе.

Праверанае рашэнне для разбору

Гэты фрагмент разлічаны на паслядоўнасць цэлых лікаў. Пусты ўвод лічыцца памылкай умовы.

from collections.abc import Sequence


def max_subarray_sum(values: Sequence[int]) -> int:
    """Максімальная сума непустога непарыўнага фрагмента."""
    if len(values) == 0:
        raise ValueError("Паслядоўнасць не павінна быць пустой")

    ending_here = best = values[0]
    for index in range(1, len(values)):
        value = values[index]
        ending_here = max(value, ending_here + value)
        best = max(best, ending_here)
    return best

Пасля апрацоўкі пазіцыі index зменная ending_here захоўвае найлепшую суму непустога фрагмента, які заканчваецца менавіта на гэтай пазіцыі. Такі фрагмент альбо пачынаецца з бягучага ліку, альбо працягвае найлепшы фрагмент, які заканчваўся на папярэднім. Зменная best захоўвае найлепшы вынік сярод ужо разгледжаных заканчэнняў.

Для звычайнага спіса абход займае лінейны час і выкарыстоўвае пастаянную дадатковую прастору. Сцвярджэнне пра час прадугледжвае пастаянны кошт доступу да элемента і звычайны для вучэбнай ацэнкі кошт арыфметыкі.

Мінімальныя праверкі:

assert max_subarray_sum([-5, -2, -7]) == -2
assert max_subarray_sum([0, 0]) == 0
assert max_subarray_sum([4, -6, 3, 2]) == 5
assert max_subarray_sum([7]) == 7

try:
    max_subarray_sum([])
except ValueError:
    pass
else:
    raise AssertionError("Пусты ўвод павінен быць адхілены")

Гэтыя тэсты карысныя для разбору канкрэтных межаў, але не з'яўляюцца доказам для ўсіх уваходных даных. Для невялікіх выпадковых паслядоўнасцей можна дадаткова параўнаць вынік з поўным пераборам усіх непустых фрагментаў.

Што спытаць пасля запуску праграмы

Папрасіце растлумачыць, чаму ініцыялізацыя нулём змяняе сэнс задачы. Затым прапануйце змяніць кантракт: дазволіць пусты фрагмент або вярнуць яшчэ і яго межы. Пры змене кантракта вучань павінен нанова вызначыць чаканы вынік і праверкі.

Нарэшце, дайце блізкую задачу без памочніка. Важна праверыць перанос ідэі, а не ўзнаўленне нядаўна ўбачанага кода. Для наступнай праверкі можна змяніць даныя і фармулёўку, захаваўшы патрабаванне самастойна назваць стан алгарытму.

Калі вучань справіўся толькі з падказкамі, гэта карысная інфармацыя для наступнага занятку. Яе не варта ператвараць у доказ самастойнага валодання тэмай.

Як ацэньваць навучальны вынік

Раздзяляйце выкананне з дапамогай, самастойнае тлумачэнне і рашэнне новага задання. Захоўвайце не толькі выніковы адказ, але і тып дапамогі: удакладненне ўмовы, навадное пытанне, гатовы контрпрыклад, фрагмент кода.

Паляпшэнне выніку з AI не даказвае паляпшэння навыку без AI. Для ацэнкі навучання патрэбныя супастаўныя самастойныя заданні да і пасля заняткаў, а пры магчымасці — адкладзеная праверка. Розніцу інтэрпрэтуюць з улікам падрыхтоўкі навучэнцаў і ўмоў навучання.

Выкладчык атрымлівае больш карысці ад дакладнага разумення памылкі канкрэтнага вучня, чым ад статыстыкі хутка здадзеных праграм. Убудаванага памочніка варта ацэньваць паводле таго, ці дапамагае ён выправіць гэтую памылку і затым абыходзіцца без той жа падказкі.
